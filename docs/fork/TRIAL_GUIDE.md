## 验收清单

1. 打开后是中文的首次设置，一路做完（或跳过）进主窗口。
2. 主窗口、设置、悬浮窗、托盘都是中文；切到 English 立即生效，两个窗口同时变。
3. 设置 → AI 模型 → 添加连接 → "自定义（OpenAI 兼容）"：Base URL 填你那个不是 `/v1` 的地址，看"实际请求地址"对不对；模型名手填；"测试对话"通过；开会时 AI 助手能流式回答。
4. 故意填错 Key：显示 401 原始错误和实际请求地址。
5. 任务路由：实时翻译选快模型、会议总结选强模型；开着实时 LLM 翻译时点 AI 助手，两边同时出字。
6. 会议音频：我 = 中文、对方 = 英文（或自动检测），各自生效；对方用 Soniox，字幕和中文译文实时出来；我用另一台机器上的远程 Whisper，能出字。
7. 翻译目标语言手填一个代码（例如 `ja`）能用；可以只翻"对方"；AI 调用日志里每句只翻一次。
8. 本地 Whisper.cpp 开 GPU 后明显比关掉快。
9. 知识库配好 embedding 端点，上传文档建索引；改过的文档重新上传后只重算改动部分（进度里显示"复用 N 块"）；中文问题能检索到。
10. 首次设置里"上传简历"能打开知识库面板；中途退出再打开能接着做。
11. 用 Claude 订阅的话：Mac 上"登录"按钮能打开终端。
12. 官方 NexQ 的数据目录 `~/Library/Application Support/com.nexq.app` 和钥匙串里的 `NexQ:*` 没变。
13. （可选）现场会议：一路音频用 Soniox，翻译选"双向"、两个语言填中文和英文，每句话按自己的语言翻成另一种（这项还没用真 Key 测过）。
14. Soniox 多区域：设置 → 语音识别 → Soniox，点"测速"看四个区的延迟；分别粘贴日本、印度等区的 Key，确认自动归到对应的区；模式选"自动（按延迟）"后开会，悬浮窗底栏的提示里显示连到了哪个区。想试换区，可以在 Soniox 控制台把最快那个区项目的并发上限调低，或者让另一个程序先占满它的并发，应该看到"某区并发已满，改连另一个区"的提示。除美国外的区要先在 Soniox 控制台申请开通。

## 2026-11-02 修复

- **中文问题检测：** 规则检测支持全角问号、中文分句、常见简繁体问法，以及“请解释”等面试提问。另已增加可选的 LLM 确认，配置与验收见下方“LLM 提问检测 M1”。
- **中文导出文件名：** 保留中文等 Unicode 字符，过滤路径分隔符和文件名禁用字符，并限制文件名长度。
- **中文词数：** 实时统计、会议详情和说话人时间轴统一使用语言分词；旧 WebView 不支持分词接口时按中文字数回退。最终字幕被修正、缩短或改归说话人时会同步校正统计。
- **会议音频热切换：** Soniox 设置与跟随全局目标的翻译语言变更，会在设置同步完成后重启识别。切换过程中继续编辑不会漏掉最后一次设置；结束会议时取消尚未执行的重启；旧会议的延迟回调不会停止新会议。识别引擎初始化失败时会关闭已打开的设备，保留会议录音状态供修正配置或结束使用。
- **结束时的最后一句：** 等待识别任务及字幕转发结束后再保存会议。远程 STT 最多等待服务器 5 秒，另留最多 2 秒转发末句；原生采集任务整体共用 10 秒结束预算。Soniox 换连接期间结束时，会用最后一条连接发送已排队的音频。Web Speech 也会先停止收音并等待末句，从悬浮窗结束时会与主窗口确认。
- **思考参数：** 原来按厂商一键填入的按钮改为只读“查看思考参数示例”，不会自动修改请求。需要按具体模型的接口文档核对后手工填写额外 JSON。
- **AI 任务并发：** 实时助手、会议总结、待办提取、书签建议和会议问答不再共用一个全局占用标记。每个请求独立取消；切换会议或离开页面会停止该页面的请求，迟到的结果不会写进另一场会议。
- **预设与快捷键提示：** 音频预设显示缺少的 Key、模型或服务器地址；未就绪时应用会提醒。快捷键注册失败会显示处理建议，同时修复换键和卸载时异步注册遗留的问题。

3. 会议中使用 Soniox，修改模型、断句参数或跟随全局的翻译目标；确认重新连接后使用最新配置。连续修改两次，再在切换过程中结束会议，确认没有重新开始收音。
4. 同时启动实时助手和历史会议总结，分别停止其中一个；另一项继续。切换历史会议时，旧任务的结果不应出现在新会议里。

## 剩余限制

- 模型是否支持关闭或降低思考由服务端决定。手工保存的不兼容参数仍可能返回 400；本次不会自动删除用户已有 JSON。
- 实时回答面板仍一次显示一个 AI 动作；同一场会议同一任务不会重复启动。Claude 订阅中共用同一个会话的任务仍顺序执行，HTTP API 或独立会话可并发。
- 网络断开、服务器长期不响应或结束等待超时，仍可能缺少最后一句；程序会有界停止，不能保证服务器返回未完成的识别结果。
- 外部程序占用的 `⌘⇧H` 不能由本 App 释放。若仍注册失败，在 设置 → 快捷键 换一个组合，或退出占用它的程序。
- 本轮只在 macOS 环境构建和测试，未提供 Windows 安装包。

## 知识库重排序（rerank）

混合检索先召回候选，再交给重排序模型按和问题的相关程度重新排序。AI 助手和“测试知识库”都走这条路。默认关闭；关闭时检索和以前完全一样，不发任何重排请求。

1. 在 **设置 → 上下文策略 → 个人知识库** 找到“重排序（rerank）”一节（在“向量化服务”下面），打开“对检索结果重排序”。和向量化服务一样，改动先进草稿，点“保存”才生效；“放弃修改”恢复已保存的值。
2. 连接：可以复用某个 OpenAI 兼容的 LLM 连接（请求发到它的 Base URL + `/rerank`，用它的 Key 和请求头；下拉里只列 OpenAI 兼容的连接），也可以单独填 Base URL、认证、请求头和 Key。Base URL 原样使用，不自动补 `/v1`，输入框下面显示实际请求地址。Key 直接存进钥匙串 `NexQPlus:rag-rerank`，`rag/config.json` 里只记是否已保存和末 4 位。
3. 模型：例如硅基流动的 `BAAI/bge-reranker-v2-m3`、Jina 的 `jina-reranker-v2-base-multilingual`、Cohere 的 `rerank-v3.5`，下拉里有这几个候选，也可以手填。TEI 只加载一个模型，可以不填。
4. 请求格式：“通用”发送 `{model, query, documents, top_n}`，适用于 Jina、Cohere、硅基流动、Xinference、vLLM、LocalAI 等；“TEI”发送 `{query, texts}`，适用于 Hugging Face Text Embeddings Inference，Base URL 填主机地址，例如 `http://<主机>:8080`。
5. 候选条数默认 30（2–200，不少于返回条数 top-K）；超时默认 2500 ms（200–60000），会议中建议 1000–3000 ms。
6. “测试连接”用三段内置文本（含中文）发一次请求，显示实际地址、耗时，以及相关段落是否排在第一；耗时超过超时设置会提醒。没保存的修改会一起测试，但不会被保存。开启后保存远程地址时，先确认“检索到的文档片段和你的问题会发送到 {host} 做重排序”。

检索时，融合后的结果先去掉重复文本，取前“候选条数”条送去重排，按新顺序取前 top-K 条。出错、超时、返回空列表，或者开启了却没填地址或模型时，沿用融合后的顺序并记一条 warn 日志，回答照常；连续失败 3 次后暂停 1 分钟（这期间不发请求），改重排序设置或 Key 后立即恢复。重排后结果的分数换成重排分数，`normalized_score` 仍以第一名为 1.0（服务返回原始 logit 时先过 sigmoid 再算，负分也保持顺序），原来的融合名次和分数保留在结果里。AI 调用日志里看到的 RAG 分数也是重排分数。AI 助手每次回答会检索两次（问题本身，问题加最近的对话），开启后每次检索各发一个重排请求。

人工验收（本次未调用真实服务、未启动或安装 App；自动测试用的是本地模拟服务）：

1. 配好重排序服务（例如硅基流动 `BAAI/bge-reranker-v2-m3`，或自建 TEI），“测试连接”显示连接成功和“相关的测试段落排在了第一位”；钥匙串里多一条 `NexQPlus:rag-rerank`。
2. 打开“测试知识库”，顶栏出现“重排序：<模型名>”。提问后统计栏显示“已重排 · N 条候选 · X ms”；每条结果的分数徽章是重排分数（悬停显示“重排分数”），旁边的“原第 N”是重排前的名次，名次上升的带绿色箭头。和关闭重排序时对比，更相关的段落应该靠前。
3. 把 Key 改错或把超时改成 200 ms：测试知识库显示“重排序失败，已沿用融合顺序”和原始错误，结果照常列出；连续问 3 次以上后显示“重排序连续失败、暂停中”；改回正确设置后，下一次检索恢复。
4. 会议中用 AI 助手提问，照常回答；AI 调用日志里 RAG 块的分数是重排分数。关掉重排序后，测试知识库里不再出现重排标记。
5. 复用 LLM 连接：选中一个 OpenAI 兼容连接后，Base URL 和 Key 输入框消失，请求发到该连接的 Base URL + `/rerank`。
6. 删除被复用的 LLM 连接：向量化服务和重排序两节都提示“这里复用的 LLM 连接已经不存在了”，显示成单独填写，不改任何字段也能点“保存”，保存后改用下面填的地址。保存之前，测试连接、索引状态和测试知识库会报“复用的 LLM 连接不可用”（英文原文 `The LLM connection reused for … can't be used`），不会再悄悄用已删除连接的地址和 Key。

## LLM 提问检测 M1

1. 在 **设置 → AI 模型 → 任务路由** 为“提问检测”单独指定连接和模型。推荐已加载到内存的本地小模型，例如 Ollama 的 Qwen3 1.7B/4B。该任务不继承默认模型；没配置、连接停用、模型缺失或请求失败时自动退回规则，不会改用其他连接。
2. 选择“规则 + 模型确认（推荐）”，或按需切到“仅规则”“仅模型”。置信度阈值默认 `0.7`，只约束模型判定；失败回退保留原规则阈值。
3. 按服务端支持的方式关闭思考，在任务参数的额外 JSON 中填写相应参数；可查看已有思考参数示例。Ollama 原生接口通常使用 `{"think": false}`。仅隐藏思考文本并不能保证服务端停止推理。检测提示词也包含 `/no_think`，但不能代替服务端设置。
4. 若服务支持 JSON 模式，在连接的兼容设置里打开“支持 JSON 模式”。检测请求会使用相应协议的 JSON 输出选项；不支持时保持关闭，解析器仍能处理代码围栏、前置思考文本和简短说明包裹的 JSON。手工额外 JSON 优先，错误的覆盖参数可能导致回退。
5. 支持 OpenAI 兼容、Ollama、Anthropic、Gemini 等 HTTP 连接，Base URL 继续原样使用，不自动补 `/v1`。Claude 订阅的会话初始化无法满足本任务的取消边界，暂不用于提问检测，已有此类路由会回退规则。

每条对方 final 原文到来后等待约 700 ms，使用最近 90 秒的双方原文（保留说话人、单独标出最新一句）判断。每场会议最多一个检测请求，期间的新句子合并为最新上下文；2.5 秒内未完成、接口失败或 JSON 不完整就用规则。本地模型首次加载可能超过此预算，可先预热。模型否决、修辞问句、非向自己提问、低于阈值的结果均不自动回答；检测到的完整问题会交给 Assist。前端继续等待对方停顿，临时字幕、自己的回答和设置变化会取消旧的自动触发。

“在 AI 调用日志中记录提问检测”默认关闭。临时开启后可在日志里查看提示词、响应和错误；这些诊断使用独立事件，不覆盖回答面板，也不保存为会议 AI 对话。

人工验收（本次未调用真实服务、未启动或安装 App）：

- 用本地模型和一次真实会议确认：中文直接提问、无问号提问、隐含请求、“那它呢？”等指代补全；对照模型判定与 Assist 实际问题。
- 说修辞问句、转述的问题、对第三人的问题，确认不会触发；自己的 final 回答在倒计时结束前到来时，旧的待触发问题停止。
- 连续快速说多句、在同一字幕段落中问两个不同问题、临时字幕不断增长，确认最多单飞、仅最新有效结果触发、后一个问题仍可触发。
- 临时停用路由或停止本地服务，确认设置页回退提示和规则检测；恢复后下一句会重试。将阈值调高，确认低置信度结果不触发。
- 切换三种模式、修改阈值和日志开关，检查另一窗口同步；结束后新开会议，确认旧请求不会写入新会议。
- 日志默认无逐句检测；开启后出现“提问检测”条目，但现有 Assist 答案不变。结束保存后检查这些诊断未混进会议 AI 问答。

## 问题预测 M2：提前准备答案

1. 在 **设置 → AI 模型 → 任务路由** 为新增的 **问题预测** 单独选择连接和模型。与 M1 一样，此路由不继承默认模型，也不会自动切换到其他连接；预测模型支持 HTTP 连接，不使用 Claude 订阅。
2. 在提问检测卡片下方打开 **预测对方接下来要问的问题**。总开关默认关闭，因为会增加模型调用和 token 消耗。M1 原有设置不变；M2 也可以配合 M1 的“仅规则”模式使用。
3. **提前生成答案** 可以单独关闭：关闭后仍显示预测问题，点击仅预览状态，不会临时请求答案。打开后按置信度顺序，最多为两题调用 **Assist** 路由；沿用 Assist 的提示词、附加指令、回答语言、原文时间窗和知识库检索。Assist 可以使用 HTTP 连接或 Claude 订阅；Claude 的预生成使用独立的 Utility 会话，不向会议会话注入假设问题。
4. 悬浮窗问题区域显示可折叠的 **对方可能会问**。默认折叠，最多三题；展开后点一题可以预览 **提前准备的答案**。这里只查看，不生成、不加入回答历史。关闭原有“自动触发”后仍可使用 M2 列表。
5. M1 确认实际问题后，本地匹配命中且答案已经准备好时，立即在主回答面板显示，带 **提前准备的答案** 标记，不再请求模型。它不会打断正在生成的回答。未命中、答案尚未完成、缓存失效时，清除这一轮预测，继续原有 Assist 行为（开启自动触发时自动生成，关闭时等待点击）。

触发与预算：只使用最近 90 秒的双方 final 原文，最多 16,000 个正文字符。累计对方新原文达到 80 字符后等待约 4 秒停顿；较短内容至少 8 字符，等待约 8 秒。临时字幕会延后触发；两轮至少相隔 25 秒，每场最多 60 轮。一个工作循环依次运行预测和最多两次预生成，不并发堆积。预测请求超时 5 秒，默认输出上限 512 token；每题准备预算 20 秒，默认输出上限 768 token（连接的任务参数仍可覆盖默认生成参数）。失败静默跳过。Claude 冷启动在取消后会等待初始化安全收尾，期间不发新问题、不发布旧答案。

复用有意保守：比较完整问题，忽略英文大小写、重复空白、结尾问号以及“请问 / please”等礼貌前缀；保留数字、小数点、否定词、实体、词序和内部标点。不用关键词重叠或子串相似度冒险命中，也不为匹配额外调用模型。换一种同义表达可能不命中，此时照常回答。短于 8 字符的指代问题不直接复用，需由 M1 补全。用户主动选择了不同的转写范围时使用新生成，避免复用不符合范围的答案。

预备答案从本轮预测完成起最多保留 90 秒。实际问题不匹配、自己开始说话、对方补充新的非问题信息、会议结束/切换，以及预测设置、模型路由、回答语言、AI 动作、场景或知识库配置变化都会使旧准备失效。设置变化不会重置本场预算。预测和未使用的答案只在内存里，只有真实问题使用过的答案按普通 Assist 回答保存。打开 **在 AI 调用日志中记录提问检测** 后，也能看到 **问题预测** 和 **答案预生成** 的独立诊断条目；这些条目不保存为会议问答。

人工验收（本轮自动化测试均用 mock；不需要用户 Key）：

- 配置本地 mock HTTP 连接，让预测任务返回 `{"questions":[{"question":"这个项目何时可以交付？","confidence":0.95},{"question":"这个项目需要多少预算？","confidence":0.85},{"question":"这个项目有哪些风险？","confidence":0.75}]}`；Assist mock 返回容易辨认的准备文本。使用 M1“仅规则”，或让检测 mock 返回同样的完整问题。
- 总开关保持关闭，输入多句双方原文并等待 10 秒：不出现预测请求。打开后，让对方讲一段上线计划；停顿后最多出现三题、两次准备请求。连续讲话和临时字幕不断更新时不提前触发；25 秒内不发第二轮预测。
- 展开“对方可能会问”，点已准备的题，检查预览与状态；主回答及会议 AI 历史不变。单独关闭“提前生成答案”后再讲一段，只有预测请求，没有 Assist 预生成。
- 重新打开准备，等待上述第一题状态为“答案已准备好”，让对方实际问“这个项目何时可以交付？”：主面板立刻显示准备文本和标记，服务端没有新 Assist 调用；结束保存后，会议 AI 对话只保留这次实际回答。
- 另起一轮后问“这个项目需要哪些人员？”：预测清空；开启自动触发时正常生成，关闭时等待点击。测试数字、否定词或对象不同的问题，确认不误用准备文本。
- 用慢 mock 分别卡住预测、HTTP 预生成、Claude Utility 初始化；关闭开关、改模型/动作配置或结束会议，再开始新会议：旧工作停止发布，旧问题与答案不出现于新会议。冷启动取消不应让后续 Claude Assist 卡在“starting”。
- 日志开关关闭时不记录预测/预生成；打开时出现两类诊断，失败记录错误但不覆盖主回答。准备过但未命中的答案和这些诊断，均不应进入会议 AI 对话。

自动化覆盖包含 Rust 的触发/冷却/预算、原文合并、单请求、取消/超时/安全收尾、严格 JSON、路由隔离、缓存命中/失效，以及前端的开关、折叠预览、旧事件过滤、即时复用、范围限制、日志和正常回答保存。
