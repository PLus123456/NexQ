# 知识库检索：回答完整度（2026-11-02）

分支 `claude/rag-retrieval-depth`（从 `custom` 切出）。目标：问论文这类长文档（5–15 万字）时，回答拿到的是完整段落而不是零散片段；说法和原文不一样的概念也能找到。借鉴了 OpenViking 的“分节摘要、层级上下文”思路，没有引入它的代码（AGPL-3.0）。

## 改了什么

设置 → 上下文策略 → 个人知识库，新增“回答完整度”一节（在“重排序”下面）。四个开关，改动立即保存：

| 开关 | 默认 | 作用 | 费用 |
|---|---|---|---|
| 扩展结果上下文 | 开 | 每个命中带上前后相邻的块（默认各 1 块）；所在小节不超过上限（默认 2000 token）时直接返回整节，也会退到更大的上级小节。同一文档里相连或重叠的命中合并成一段，块之间的重叠去掉，跨进新小节时写出该小节标题。每次检索的总量有上限（默认 16000 token），超过后排在后面的命中只返回自身 | 不调 LLM，提示词变长 |
| 按标题切分 | 开 | 先按标题切成小节，分块不跨小节；每块带标题路径（如“第三章 研究方法 › 3.2 数据来源”），向量化和关键词索引都包含这条路径，给模型的来源标签也带上 | 无 |
| 查询改写（多路查询） | 关 | 检索前让 LLM 把问题改写成 1–5 种说法（默认 3），每种都走原来的混合检索（BM25 + 向量），结果用 RRF 融合（原问题权重 1，改写 0.8，`retrieval.rrf_k` 不变），再按原问题重排序。有硬超时（默认 5 秒）；失败、超时或没给出可用结果就只用原问题 | 每次检索 1 次 LLM 调用 |
| 章节摘要 | 关 | 建索引时为每一章写一段摘要，单独存成一条记录，和正文一起向量化、参与检索，标签是“章节摘要”。章节内容没变就沿用旧摘要。摘要、目录、参考文献、致谢、附录不写摘要；只有一块长的章节也不写 | 每章 1 次 LLM 调用 |

标题从哪来：

- Markdown 的 `#` 标题。
- Word：标题样式（含中文 Word 的样式 ID “1/2/3”、WPS 的“标题 N”、基于标题样式的自定义样式）和段落大纲级别，提取时转成 `#` 标记。
- PDF：读书签（outline），和书签标题一致的行标成标题。没有书签就用下面的编号规则。
- 纯文本或无书签的 PDF：“第一章 / 第二节”“1 绪论 / 3.2 数据来源 / 3.2.1 xxx”“一、/（一）”“Chapter 3”，以及“摘要、目录、参考文献、致谢、附录”等。带句号逗号的句子、目录行（点线或页码结尾）、表格行、网址不算标题；页眉里重复出现的章标题只删掉这一行，不打断当前小节。

LLM 任务：设置 → AI 模型 → 任务路由里多了“知识库查询改写”（`rag_query_rewrite`）和“知识库章节摘要”（`rag_summary`），没单独设置时跟随默认路由。查询改写每次检索都会先调用，标了“高频”，适合选关思考的快速模型。

“测试知识库”对话框：结果卡片显示标题路径、合并后的块范围（如 `#11–14`）和“章节摘要”标记；开了查询改写会显示同时检索了哪些说法，失败或超时也会显示。

会议中的 AI 助手：原来分别用“问题”和“问题 + 转写”各搜一次再按分数合并，现在两条一起交给检索融合成一个列表，扩展后的段落不会重复出现。

## 怎么重新索引

1. 装新版后第一次打开，旧配置会自动改成“按标题切分”（配置版本 2 → 3，只改一次；之后手动关掉不会再被改回）。
2. 打开知识库设置，“索引状态”会提示“需要重建索引”，原因是“分块、标题或摘要设置已变”。点“重建索引”→“确认重建”。正文没变的块保留原向量，只有新切出来的块需要重新向量化（标题路径变了的块会重算）。
3. 想要章节摘要：先在任务路由里确认“知识库章节摘要”用的模型，再打开“章节摘要”，再重建一次。进度里会显示“正在为 xxx 写章节摘要：第几章”。某章摘要失败时文档照常可搜，只是会一直提示需要重建；再点重建会补写失败的章节。
4. 查询改写和上下文扩展不需要重建，打开就生效。

## 兼容性

- `rag.db` 升到 schema v2（`rag_chunks` 加了 `heading`、`kind`、`source_hash` 三列），打开时原地升级，旧数据保留。之后旧版 NexQ Plus 打不开这个索引（会提示“由更新的版本写入”），需要回旧版时重置索引即可。
- 选“递归切分”（关掉“按标题切分”）时分块结果和以前完全一样，原向量都能复用。
- 检索接口多了 `queries`、`rewrite` 字段，结果多了 `heading`、`chunk_range`；旧字段不变。

## 代码位置

- `src-tauri/src/rag/headings.rs`：标题识别、小节和章节划分。
- `src-tauri/src/rag/chunker.rs`：`headings` 策略，块不跨小节。
- `src-tauri/src/rag/file_processor.rs`：Word 标题样式、PDF 书签。
- `src-tauri/src/rag/expand.rs`：上下文扩展、合并、预算。
- `src-tauri/src/rag/rewrite.rs`：改写提示词和结果解析；`engine.rs` 的 `search_queries` 做多路检索和融合。
- `src-tauri/src/rag/indexer.rs`：章节摘要。`store.rs`：schema v2。
- `src/settings/rag/RetrievalSection.tsx`：设置界面。
